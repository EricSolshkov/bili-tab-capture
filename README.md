# BiliTabCapture

## barline 小节任务交接（开发版）

配套 `bilibili-evolved-barline` 的交接改动位于独立仓库，需要使用含交接功能的版本；其小节设置面板提供“发送到 BiliTabCapture”。先启动本应用，在网页端填写起止小节、4–7 弦和本地应用地址，然后选择“打开并发送”，或导出 `.barlist.json` 拖入本应用。地址应与启动日志一致；端口被占用时可能不是 5000。网页按钮不会启动尚未运行的桌面程序。

两种方式使用同一个 `bili-tab-capture/barlist` v1 协议。一键交接使用 URL fragment（任务不进入 URL 查询参数），不需要开放跨域接口；较大任务自动提示改用文件。旧版“全部配置备份”不是转谱任务，需在新版 barline 中选择范围重新导出。

导入后自动定位 BV/cid/分P，保留拍号、四分音符 BPM、小节时间及顺序。调整谱面裁切范围后点击“生成图片”：每小节在区间内取三个候选时刻，保留候选图，按清晰度选一张展示；相同画面不会跨小节去重。空白、取帧失败或超出视频时长的小节仍保留在覆盖表中。隐藏图片会显示为待处理，小节任务不允许拖动排序。时间表与截图的谱面对应关系仍需人工核对，覆盖率不是 OMR 准确率。

小节任务、候选图片与检查状态随历史记录恢复。不同任务内容使用独立缓存目录，同一分P已下载的视频可通过硬链接（不可用时复制）复用。协议保留 `stringCount`（4/5/6/7）、高音弦到低音弦的可选 `tuningMidi` 和 `capo`；不会根据弦数猜测吉他/贝斯调弦。当前版本已打通交接、按小节取图、整行自动关联、全局校对与 PDF 排版；尚未接入 OMR/GP 导出。

开发验证：

```powershell
.venv/Scripts/python -m unittest discover -s tests -v
.venv/Scripts/python -m py_compile app.py barlist.py bili.py tab_extractor.py runtime_paths.py pdf_render.py
node --check static/app.js
```

测试用视频：`https://www.bilibili.com/video/BV1iR2iB5Ejk`。仓库附带 1–8 和 1–116 小节 JSON 样例（首拍 0.177 秒、150 BPM、4/4），可直接拖入应用测试；`tests/test_barlist.py` 使用自动生成的视频测试重复画面、空白小节和越界，不把合成时间表视作此曲的真实标注。

## 新增功能

### 支持更多种类的视频
- 方便地拖拽上传本地文件
- 通过哔哩哔哩BV号导入视频
- 登录哔哩哔哩账号获取更高分辨率视频
- 谱面背景为彩色的视频
- 全屏动态谱视频
- 不同段落的谱面高度不一致的视频
- 从图片导入谱面进行排版

### 支持手动调整
- 调整图片缩放
- 裁切或删去截图，去除重复部分
- 补插两次截图间隔之间缺失的截图
- 图像反色，去除彩色背景，自定义背景及字体颜色
- 页边距，图片间距设置
- 图像水平和竖直的对齐设置
- 纸张横竖方向设置
- 标题支持非英文字符
- 实时预览调整效果
- 更方便的视频时间裁切及预览

### 其他功能
- 导出为长图
- 自动识别小节线
- 自动裁剪去重

## 从源码运行

### 整行谱面校对（barlist 任务）

完成取图后，第 3 步默认进入整行工作台。相邻近似画面合成候选组，原始取图记录不删除；滚动或换行的画面保留为不同组。

1. 默认以候选截图的实际时间定位 barlist，再用播放高亮所在区间投票推断整行关联。证据一致的行自动采用，重叠小节自动略过；无可靠高亮或投票冲突的行标为“需关注”。不把谱面印刷编号当作演奏序号。
2. 点击小节右上的 × 略过重复区间，或恢复、增删边界、排除/移动整行：后续所有有效区间按 barlist 全局顺延，编号、回放和导出共用同一关联。无需逐行填号。未知行仍保留待确认状态。
3. 修改自动保存，可撤销本页最近 30 次编辑。高级调整中可从某行设一个对齐点，统一调整后续内容；也可换图、裁剪上下边缘及设置 4–7 弦。
4. 点击编号回看视频；只需关注不确定的行。确认推断合理后可“采用当前推断并全局顺排”。缺失、重复、越界、乱序及未确认行都会阻止完整小节 ZIP 导出；PDF 流程可先应用已确认部分。
5. 列表底部“应用结果并进入逐图调整”会把已确认区间按顺序传入原来的卡片/PDF 流程，保留裁剪和小节线；重复区间、排除行和未确认行不传入。底部显示实际应用数量及缺失信息。中间有略过区间时拆成独立卡片，重复演奏的同源图也有独立卡片身份。再次应用替换卡片调整，原始截图和行校对仍保留。
6. 下载 ZIP，内含按 barlist 顺序编号的单小节 PNG 与 `manifest.json`（时间、原小节 ID、弦数、来源图及裁剪框）。这仍是图片输入包，不是 GP 文件。

小节线检测以投影统计为主：横向响应分布分离出峰值，以等间距峰群定位谱表；纵向稳健投影结合弦间响应，使用 Otsu 分离峰值，使用 MAD 排除强度波动异常的伪峰。可展开横/竖投影曲线。时间戳只能锚定正在演奏的小节，不能单独确定整幅静态谱面的覆盖范围，因此同时利用画面分组、区间与高亮证据；无高亮视频可能仍需一次全局对齐及局部修正。

行校对保存在任务 `state.json` 的 `score_rows` / `score_string_count` 中；重取图片会清除旧行校对。原始 barlist 弦数保持可追溯，图片包采用校对后的弦数；弦数改变时不会沿用不匹配的调弦数组。旧的逐图/PDF 排版入口仍可切换。

验证：`python -m unittest discover -s tests -v`，`node --check static/app.js`，`node --check static/score_rows.js`。测试覆盖 4–7 根线、浅色/反色/断点、非谱面拒识、重复演奏分组、保存恢复以及 ZIP 数据对应关系。全局联动测试：`node --test tests/score_sequence.test.cjs`。指定视频完整 116 小节试算可自动覆盖 114 小节，片尾画面重置后的关联仍需关注；未进行跨视频准确率评测。
